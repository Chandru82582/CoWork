# High-Performance Parallel Data Ingestion Pipeline

This project provides a high-performance data ingestion script (`datainsertion.py`) designed to efficiently and reliably transfer large volumes of data from a CSV file into a relational MySQL database. It uses Python, SQLAlchemy for ORM, and the `multiprocessing` module to achieve significant speed improvements over traditional single-threaded methods.

## Core Features

- **High-Speed Ingestion**: Leverages multiprocessing to parallelize the insertion of data, utilizing all available CPU cores.
- **Data Integrity**: Implements a two-phase architecture to prevent database deadlocks and race conditions.
- **Robust Error Handling**: Gracefully handles common data quality issues (e.g., duplicate primary keys, inconsistent data) and logs them without halting the entire process.
- **Automated Setup**: Automatically creates the database and tables if they do not exist.
- **Detailed Logging**: Provides comprehensive logging to both the console and a file (`data_insertion.log`) for progress tracking and debugging.

## Architectural Overview

To maximize performance while ensuring data integrity, the script employs a two-phase strategy:

### Phase 1: Synchronous Parent Table Pre-population

This initial phase is executed by the main process and is designed to eliminate the primary source of concurrency conflicts: the creation of shared, parent records (`Location` and `TelecomPartner`).

1.  **Read and Analyze**: The main process reads the entire CSV file into memory.
2.  **Deduplicate Parent Records**: It iterates through all rows to identify unique `TelecomPartner` and `Location` records.
    - **Data Cleansing**: A critical step here is handling data inconsistencies. For `Location` records, a dictionary is used with the `pincode` as the key. This ensures that even if the source CSV has multiple entries for the same pincode, only the *first one encountered* is treated as the canonical record, preventing primary key violations.
3.  **Bulk Insert**: The script queries the database to see which of these unique parent records already exist. It then performs a `bulk_save_objects()` operation to insert only the new records. This is highly efficient as it minimizes database round-trips.
4.  **Foreign Key Mapping**: After ensuring all parent records exist, the main process queries them back to create a `partner_name -> partner_id` mapping. This map is used to enrich the in-memory CSV data, adding the correct `telecom_partner_id` foreign key to each customer row.

By completing this phase first, we guarantee that when the parallel workers start, they will never need to create or lock the `telecom_partner` or `locations` tables.

### Phase 2: Parallel Child Table Ingestion

This phase is where the heavy lifting occurs, distributed across multiple CPU cores.

1.  **Data Chunking**: The main process divides the list of enriched customer rows into smaller, roughly equal-sized "chunks." The number of chunks is determined by the number of available CPU cores (`multiprocessing.cpu_count()`).
2.  **Worker Pool**: A `multiprocessing.Pool` is created to manage a pool of worker processes.
3.  **Distribute Work**: The `pool.map()` function distributes one chunk of data to each worker process.
4.  **Independent Worker Execution**: Each worker process executes its task in isolation. Crucially, each worker:
    - Creates its **own independent database engine and session**. SQLAlchemy objects are not process-safe, so this isolation is mandatory.
    - Iterates through its chunk, creating `Customer` and `CustomerUsage` objects.
    - Performs a **single `session.commit()`** at the end of its work, wrapping all inserts into one atomic and efficient database transaction.

## Prerequisites

- Python 3.8+
- MySQL Server

## Setup and Execution

1.  **Clone the Repository**:
    ```shell
    git clone "https://github.com/Chandru82582/TelecomDataMulti"
    cd TelecomDataMulti
    ```

2.  **Install Dependencies**:
    This project uses SQLAlchemy and other libraries. Install them using pip:
    ```shell
    pip install sqlalchemy mysql-connector-python sqlalchemy-utils
    ```

3.  **Configure Database Connection**:
    Open the `datainsertion.py` file and update the `DB_CONNECTION_STRING` with your MySQL details.

    ```python
    # e.g., "mysql+mysqlconnector://user:password@host/database_name"
    DB_CONNECTION_STRING = "mysql+mysqlconnector://root:root@localhost/telecom_db"
    ```
    The script will automatically create the database (`telecom_db` in this example) if it doesn't exist.

4.  **Place CSV File**:
    Ensure your `telecom_churn.csv` file is in the `TelecomDataMulti` directory.

5.  **Run the Script**:
    Execute the script from your terminal.
    ```shell
    python datainsertion.py
    ```

    You will see log messages in your console indicating the script's progress. A detailed log file, `data_insertion.log`, will also be created in the same directory.

## Future Improvements

- **Memory Optimization**: For extremely large CSV files that do not fit in memory, the script could be adapted to read the CSV in chunks in the main process as well.
- **Transactional Retries**: Implement a retry mechanism with exponential backoff for transactions that fail due to transient issues like deadlocks (though the current architecture is designed to prevent them).
